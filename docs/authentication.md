# 账户登录与注册

登录页提供账号密码、手机验证码和邮箱密码三项切换，底部的“没有账号？去注册”打开注册表单；注册后自动登录，也可返回登录。界面不展示部署或数据库说明。

## 页面与交互

登录、注册与找回密码说明使用统一的蓝白分栏卡片、账号安全插画和蓝色主按钮；手机端集中展示表单。登录方式支持键盘左右切换，输入框有明确标签，密码可切换可见性。

“记住账号”仅在成功登录后保存所选账号或邮箱，不保存密码，不改变服务端会话时长。取消勾选并成功登录后删除这份偏好；新注册表单与登录表单分别保留非密码输入。

“忘记密码”打开当前能力说明与返回登录入口；自助重置尚未接入，不展示可提交的重置表单。页面仅显示可用的登录操作。

## 设置中的账号管理与工作空间

侧栏底部提供“设置”入口，原“我的工作空间”资料入口与首页统计已移入设置页。设置页展示当前账号、邮箱、收藏提示词、知识资料和对话数量；统计随当前账号切换。

“退出当前账号”结束当前浏览器会话。“添加其他账号登录”打开独立登录流程，也可从中注册新账号；登录成功后切换到该账号的工作空间。登录失败、按 Esc 或点击“返回当前账号”会保留原会话；返回时重新核对服务端账号和工作空间。

有未同步修改、冲突或未发送内容时先提示保留内容；模型正在回复时暂不添加账号。账号切换清理旧界面和模型状态，不将旧请求结果写入另一账号。浏览器使用当前登录会话，不保存其他账号的密码或会话列表。

## 账号与邮箱

注册需填写 3–32 位字母、数字、下划线或短横线组成的账号、邮箱和 10–128 字符密码。账号与邮箱均唯一，登录匹配忽略大小写。注册邮箱目前作为登录标识使用，尚未接入邮箱归属验证与密码找回邮件。

注册接口为 POST /api/register。账号密码与邮箱密码登录均使用 POST /api/login，分别传入 method=account、account、password，或 method=email、email、password。

每个账号有独立工作空间和登录会话。GET /api/status 返回当前已登录账号，GET /api/workspace 返回 userId 与修订号；新版 PUT 请求包含 userId，避免同一浏览器其他标签页切换账号后覆盖另一账号的数据。前端待发送缓存也按实例和账号区分。

## 兼容原有密码用户

旧版访问密码自动兼容为账号 admin，密码与原有工作空间保持不变。旧登录会话继续有效。首次新建的账号作为旧版兼容账号；兼容账号的工作空间保存同时维护旧数据表，支持现有代码回退流程。

新增账号使用独立的数据表记录，不会自动导入原账号的浏览器缓存。退出或切换账号时，界面清理上一账号的表单、输入草稿和显示数据。

模型对话请求也绑定当前账号；新账号的回复缓存与上游请求编号分别隔离，原有兼容账号继续使用旧编号以恢复已有回复。退出或切换账号后，不将进行中的旧回复写入另一个账号的界面。局域网/域名入口转发相同的登录资源、注册和账号/邮箱登录接口，工作空间仍由真实后端保存。

没有删除旧表、重置密码或清空业务数据。原有数据库备份和持久卷继续使用。

## 手机验证码

短信启用时显示手机号、验证码和获取验证码操作。发送成功后开始倒计时。

当前未配置短信平台。POST /api/sms/send 和 POST /api/login/sms 返回明确的 sms_unavailable，不发送短信，也不使用固定或演示验证码完成登录。GET /api/status 的 authMethods.sms 为 false；短信标签页显示服务状态，并提供返回账号密码登录的入口。

实际启用短信登录还需配置短信服务、验证码生成与一次性验证、频率限制和手机号与账号的绑定。服务凭据只通过服务端配置，不写入浏览器或公开仓库。

## 验收

应用测试覆盖注册、账号/邮箱登录、会话持久化、重复账号和邮箱、旧数据库迁移、代码回退后的旧表更新、工作空间隔离与过期标签页的账号绑定。

CI 的 auth-ui 任务使用独立测试数据库与 Chrome，检查三种方式切换、注册返回、密码显示、错误反馈、旧账号和新账号数据隔离，以及 320px/390px 手机布局，并保存 authentication-previews 截图产物。
