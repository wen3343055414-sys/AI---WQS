# 智作台服务端

管理入口：**http://127.0.0.1:3100**。原工作台入口仍为 http://127.0.0.1:3000。

这是独立的 Node.js 管理服务，直接读取本机 Docker 状态并执行固定的管理操作。工作台前后端停止时，管理后台仍可以访问。运行时只使用 Node.js 和 Python 标准库，没有新增第三方生产依赖。

## 第一次使用

打开管理入口，自行设置一个 **10–128 个字符的独立管理密码**。此密码与工作台密码分别保存，没有预设密码。设置和登录后可以使用：

- **服务器总览**：真实服务健康状态、CPU、内存、备份数量、主机资源与当前版本；显示当前模型、今日及累计 Token、输入/输出、缓存命中、请求结果和最近 12 次用量。CPU 图表在页面打开期间每 8 秒采样。
- **服务管理**：启动、停止、重启工作台前后端，保留持久卷中的数据库和备份。
- **运行日志**：查看后端、前端、更新器和管理服务的最近日志。
- **数据备份**：创建一致性数据库快照、查看已有快照、下载 SQLite 备份。
- **版本与更新**：复用现有 CI 验收、升级前备份和失败回退规则；可暂停或恢复每分钟自动更新。有上一运行版本后才允许回退。
- **操作记录**：查看最近管理任务的结果和输出，以及登录、服务操作和下载记录。
- **API 接口设置**：管理多个服务商连接及独立加密密钥，获取或手动添加模型，启停、修改显示名称、设置默认模型；按服务商查看 Token 和设置月限额。
- **域名与网站**：查看并管理真实工作台的本机与局域网入口、部署状态及域名/证书检测结果；在同一网络中的其他设备和浏览器登录同一服务器。

停止工作台时，先暂停自动更新，防止定时器重新启动应用。再次启动时恢复停止前的更新设置；用户原本已暂停自动更新的情况会继续保持暂停。操作与原有更新器共用同一个锁，避免部署和启停同时执行。

## 运行方式

已注册 Windows 任务计划 **AI-WQS Server Admin**，在当前用户登录后自动运行。管理服务通过 `scripts/launcher.py` 启动 Node.js，不弹出控制台窗口。工作台原有的 **AI-WQS Local Server Update** 任务继续负责版本更新。

只监听 `127.0.0.1:3100`，没有对局域网或公网开放。运行任务使用当前用户权限，不需要保存 Windows 登录密码。电脑休眠、关机或退出用户登录时不保证持续服务；这里没有配置无需登录的系统级 Windows 服务。

目录结构：

```text
AI-WQS-admin/
  config.json                 本机端口、路径和可执行文件位置
  src/server.js               HTTP 接口、访问与请求校验
  src/store.js                独立登录、任务与操作记录
  src/system.js               Docker 状态、日志和备份读取
  public/                     中文管理界面
  scripts/control.py          复用现有更新器的受限管理操作
  scripts/task_control.py     只管理指定的更新任务
  scripts/launcher.py          无控制台启动入口
  scripts/install.py           注册并启动本机任务
  data/admin.sqlite           管理密码哈希、会话、任务和操作记录
  data/maintenance.json       主动停止与自动更新恢复设置
  server.log                  管理服务日志
  tests/                      接口、安全与服务控制测试
```

现有工作台数据仍保存在 Docker 持久卷 `ai-wqs-server_workspace-data` 中。管理后台不会把工作台业务数据复制进自己的数据库。备份下载使用临时文件，传输完成后清理临时副本。数据库占用包含主 SQLite 文件与 WAL 文件；快照大小可能与当前占用不同。

管理会话有效期为 8 小时，Cookie 使用 HttpOnly 和 SameSite=Strict。密码只保存加盐 scrypt 哈希。状态和操作接口需要登录；变更请求另行验证来源和会话校验值。没有任意命令执行接口，也没有数据库删除或覆盖恢复入口。

## 域名与网站：本地工作台访问

打开左侧 **域名与网站**，使用“域名管理 / 网站部署 / SSL 证书”三个视图。局域网地址来自本机正在使用的物理网络接口，VPN、Docker、WSL、回环与伪 IP 不作为跨设备地址展示。页面不再包含独立静态站点编辑器；旧版网站草稿继续保留在原数据库，不自动删除。

网关默认端口为 `3200`，固定转发本机 `3000` 工作台的真实页面和业务接口，支持登录、会话、提示词、资料、模型配置与对话。其他设备在同一局域网中打开页面显示的 `http://局域网IP:3200`，使用原工作台访问密码登录。不同浏览器使用独立登录 Cookie，访问同一服务器和数据库。上游工作台不可用时返回实际错误，不切换为静态或浏览器演示模式。

管理端仍只监听 `127.0.0.1:3100`。网关只接受允许的 Host 和本机/物理局域网网段客户端，仅代理明确列出的工作台路径；不转发管理端、内部模型接口或任意服务器文件。网关不允许远程初始化工作台，必须先在本机设置访问密码，再启用局域网访问。

局域网开关和修订持久保存在稳定管理数据库。启用应用开关后，还需 Windows 防火墙允许同一局域网访问端口；管理员可以运行已审核的 [防火墙配置脚本](scripts/configure-lan-firewall.ps1)，只管理专用规则 `AI-WQS-LAN-Gateway`、指定 Node 程序及网关端口，远端范围限制为 `LocalSubnet`。不会停用防火墙或开放管理端口。具体安装与验收见 [本地部署说明](docs/domain-access.md)。

默认局域网入口使用 HTTP，界面如实显示“未启用 SSL”。DNS 和证书状态只根据实际解析、TLS 及工作台实例比对结果显示。添加域名仅保存待验证配置，必须拥有 DNS 管理权限并实际设置路由；保存一个名称不代表域名已经生效。DHCP 地址随网络分配可能改变，长期固定需要在路由器中预留地址。

本地模式默认不恢复旧的临时公网通道。公网访问需要显式启用服务配置 `enablePublicAccess` 并另行配置受控入口，不能将他人持有域名的子域名当作自己可注册的域名。

## 模型 API 接口设置

打开 **API 接口设置 → 添加服务商**，选择国内、海外、本机或自定义模板。支持多个同名服务商的独立连接，每个连接分别保存协议、地址、密钥、超时和月 Token 限额。模板只提供地址、协议和官方文档；模型 ID 以当前账户提供的目录为准。

填写服务商提供的 Base URL（例如包含 `/v1` 的基础地址），不要填写完整的 `/chat/completions`、`/messages` 或 `/models` 路径。支持 OpenAI Chat Completions 兼容、Anthropic Messages 和 Gemini generateContent 原生协议。本机模型可使用 `http://127.0.0.1:端口/v1`，远程接口使用 HTTPS；账户地域和业务空间必须与地址匹配。

密钥由用户自行在页面中输入，使用当前 Windows 用户的 DPAPI 加密后保存在本机管理数据库中。页面和接口响应只提供“是否已保存”，不回传密钥明文。留空保留原密钥，输入新值可替换；清除本机密钥需要勾选相应选项。更换接口来源或协议时需要重新输入密钥，防止转发旧凭据。各连接独立保管凭据，前端和 Docker 后端均不会获得服务商密钥。

保存连接后，点击 **获取模型 / 检测连接**，按所选协议读取模型目录。此操作发送该连接的认证信息，不发送工作台对话内容或生成模型回复。新发现的模型默认停用；只启用需要使用的文本对话模型，再选择 **设为默认**。不提供目录的接口可以手动添加精确模型 ID。目录可访问不等于账户有对话权限或额度。

检测不自动跟随重定向，也不访问链路本地/云元数据地址。认证、证书、网络、超时等失败会显示明确结果，不把上游原始错误内容写入记录。未保存的修改有切换保护，配置版本检查防止覆盖其他页面的新修改。

**1.3 版支持多模型真实对话**：工作台通过受认证的本机后端和内部通道调用管理服务，由服务端选择对应的连接、协议和加密凭据。工作台约每 8 秒刷新可选模型及默认设置。输入框的模型选择器可以跟随服务端默认，或选择其他已启用模型；每个请求固定所选模型，失败时不会自动切换其他服务商。

总览只累计此管理服务实际收到的模型请求及接口返回的 `usage`，按北京时间划分今日用量。不包含接入前或其他应用的用量，也不推算账户余额或费用。未返回用量、超时或连接中断的请求显示未知用量，不冒充 0 Token；服务商可能仍对中断请求收费。缓存命中数已经包含在输入 Token 中。

**用量与限额**按连接汇总本月已报告 Token、累计输入/输出、请求结果和未知用量。月限额为 0 时不限额；达到后拒绝新请求，进行中的请求可能超额，缺失 usage 的请求无法精确计入。此规则不等于服务商账单硬上限。移除连接或模型后保留历史用量。

既有单接口配置首次升级自动迁移，保留加密密钥和默认模型，不需要重新输入 DeepSeek 凭据。多模型表与旧兼容快照并存；回退旧代码时，OpenAI 兼容默认模型可继续使用，Claude/Gemini 原生默认模型会暂停，防止按错误协议发送。多模型配置应在当前版本管理。详细设计及调研来源见 [多模型说明](../docs/multi-model-settings.md)。

工作台支持多轮、等待提示、失败原因、手动重试和重新生成，旧演示会话保留原标记。请求去重避免同一请求被重复调用；工作台数据库保留 7 天回复缓存用于恢复，管理数据库只保留用量元数据，不保存对话正文。管理服务重启后无法确认的请求不会静默重新提交。

工作台、管理服务和更新器源代码现在统一位于同一 GitHub 仓库。带有 Windows 发布清单的新提交直接使用仓库源码；旧的 `integration/` 补丁只用于过渡版本回退。管理启动器跟随同一已验收提交，在任务和模型请求完成后切换代码，数据及配置留在稳定运行目录。流程见 [代码同步说明](../docs/source-sync.md)，接口说明见 [model-integration.md](docs/model-integration.md)。

## 维护与验证

在本目录中运行：

```powershell
npm test
```

Python 控制测试可按实际配置调用：

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
```

在已经安装的稳定管理运行目录中，可以重新启动任务。不要在 Git 工作副本或不可变发布目录内执行安装脚本：

```powershell
python scripts/install.py
```

移动整个目录前需要同步修改任务计划和配置文件中的绝对路径。不要删除 `data/` 或工作台持久卷，否则会丢失相应的管理信息或业务数据。Node.js 与 Python 路径保存在本机配置中；运行环境迁移后可在配置文件中调整。

仓库测试覆盖接口权限、Windows DPAPI、API 配置、真实模型调用链、用量、更新与回退。模型请求使用隔离测试服务，不依赖真实服务商账号；当前验证结果记录在仓库公开工作日志中。
