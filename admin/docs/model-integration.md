# 真实模型接入（1.2）

工作台入口：`http://127.0.0.1:3000`。服务端入口：`http://127.0.0.1:3100`。

## 调用与同步

1. 在服务端保存 Base URL、密钥和精确模型 ID，点击测试连接可读取模型列表。
2. 工作台登录后通过 `/api/model-config` 自动读取模型名称和就绪状态，无需在前端再次设置密钥。
3. 工作台 `/api/chat` 验证访问会话和来源，使用仅后端挂载的内部令牌访问管理服务的 `/internal/model/chat`。
4. 管理服务每次读取当前配置，在内存中解密密钥，使用 HTTPS 请求模型接口。HTTP 仅允许本机测试或本地模型。
5. 对话保存在原有工作台数据库；管理服务只保存模型名称、请求状态、时间和 Token 元数据。

默认输出上限 4096 Token，回复达到上限时提示用户继续。对话最多 80 条、合计 120,000 字符；超限提示新建会话，不静默丢弃上下文。现有助手选项作为通用、写作和编程提示风格，模型由服务端统一选择。DeepSeek 使用非思考模式提供直接回复，不返回或存储 reasoning_content。

没有配置、认证失败、余额不足、限流、超时和异常响应均显示失败，绝不回退为演示回答。一次最多两个请求，每分钟最多 20 个新请求。请求没有自动重试；手动重新请求会使用新的请求编号。

## 用量

服务端总览和受保护的 `/api/model-usage` 返回今日、累计及最近 12 次用量。输入、输出、总量和缓存命中均来自服务商响应。缺失或无效的 usage 记为未知；缓存命中已计入输入总数。统计不等于服务商账户全部消耗，不包含其他应用或接入前请求。

统计存放于 `data/admin.sqlite` 的 `model_usage` 表，重启保留；不记录请求正文、回复正文、密钥或原始服务商错误。工作台 `model_replies` 表保存最近 7 天回复，用于恢复和去重，与原有业务数据使用同一个 Docker 持久卷。

## 部署与恢复

`AI-WQS-local/config.json` 的 `modelIntegration` 为 true 时，新版本通过 `ops/windows/release.json` 声明原生模型桥接，直接构建仓库源码并应用 `ops/windows/compose.models.yaml`。旧版本仍可通过安装目录的 `integration/prepare.py` 生成受保护补丁构建，用于回退。原始 `releases/<sha>` 保持不变。镜像标签增加 `-models-v1`，工作台状态版本增加同样后缀，打开的旧页面可检测版本变化并安全刷新。

密钥仍由 Windows DPAPI 绑定当前用户保护。内部令牌文件 `data/model-bridge-token` 只读挂载给后端；不要放进公开仓库、浏览器存储或日志。服务端先启动，工作台才可以发送模型请求。

管理服务跟随相同提交，通过稳定启动器从 `releases/<sha>/admin` 读取代码和静态资源；配置、账号、凭据和统计由 `AI_WQS_ADMIN_HOME` 指定的本机目录保存。版本切换失败时恢复代码，不覆盖业务数据库。完整说明见 [代码同步流程](../../docs/source-sync.md)。

Node 测试覆盖真实回复与演示历史兼容、去重与重启恢复、最新配置读取、实际用量、鉴权、余额不足、重定向、超时和响应边界。Windows 更新器与控制测试另行执行；上游 Linux 更新器依赖 fcntl，在 Linux CI 中运行。
