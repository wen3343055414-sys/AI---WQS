# 域名与网站：局域网部署

本模块把独立管理端与真实工作台访问入口分开。

| 入口 | 用途 | 监听与访问范围 |
| --- | --- | --- |
| `127.0.0.1:3100` | 服务端管理 | 仅本机，独立管理密码 |
| `127.0.0.1:3000` | 工作台原入口 | 仅本机，原有工作台密码 |
| `局域网IP:3200` | 手机、其他电脑及浏览器访问工作台 | 物理局域网网段，原有工作台密码 |

网关保持真实页面、登录、数据保存、模型桥接与聊天行为。不同设备登录后使用同一工作台数据库，乐观锁会提示并发保存冲突。网关故障或工作台离线时报告错误，不替换为演示页面。

## 启用

1. 在本机打开工作台，完成初始密码设置并确认能够登录。
2. 在管理端“域名与网站 → 网站部署”中启用局域网访问。
3. 电脑连接 Wi-Fi 或网线，并确认页面已检测到物理局域网地址。
4. Windows 防火墙需要一次管理员操作，只放行工作台网关。使用管理员 PowerShell 运行已接受版本中的脚本：

```powershell
powershell -NoProfile -ExecutionPolicy RemoteSigned -File C:\path\to\accepted-release\admin\scripts\configure-lan-firewall.ps1 -AdminHome C:\path\to\AI-WQS-admin
```

`AdminHome` 指向已安装的稳定管理目录，必须包含有效的 `config.json`。脚本以实际 `node` 路径和 `websitePort`（默认 3200）创建或更新 `AI-WQS-LAN-Gateway` 规则，仅允许 `LocalSubnet`。脚本需要 Windows 管理员权限；普通运行账户无法代替管理员授权。不会改变网络类别、DHCP、路由器设置或其他防火墙规则。

5. 另一设备连接同一局域网，打开页面给出的完整 HTTP 地址，使用原工作台密码登录。管理端仍只从本机打开。

## 地址与状态

- 物理网络地址会自动刷新。没有局域网连接时显示未检测到，不提供虚构地址。Windows 网络探测失败时拒绝非回环访问，等待探测恢复。
- 页面显示“监听中”表示应用网关及上游已就绪，不代表已经从另一台物理设备完成验收。防火墙状态单独显示，无法核实时显示未知。
- DHCP 分配的地址可能改变。需要长期稳定时，在路由器中为服务器保留地址；不要随意改用一个未保留的静态地址，以免冲突。
- 当前局域网入口使用 HTTP，证书视图如实显示未配置。不会将自签名证书描述为所有浏览器已信任的 HTTPS。
- 公网域名需要拥有 DNS 管理权限。域名检测检查真实 DNS、有效 TLS 及 `/api/status` 的服务器实例；未完成配置的记录保持待验证，不伪造成功。

## 停用和回退

可在“网站部署”中停用局域网入口，开关持久保存，原工作台本机入口不受影响。旧版静态网站草稿仍在管理数据库中。升级继续使用原有一致性备份和代码回退规则，不删除用户业务内容。
